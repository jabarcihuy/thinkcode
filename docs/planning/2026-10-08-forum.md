# Forum Quethink — 8 October 2026

User-authorized scope: mobile-first discussion topics and replies, including database questions and general discussion. This supersedes the previous forum/social non-goal only for this bounded discussion feature. No likes, badges, private messaging, notifications, uploads or course-completion credit.

## Interaction

- Forum is reachable from the expanded mobile menu and desktop account navigation.
- Registered USER/ADMIN accounts create topics and replies. Named guests read visible discussions and receive an account CTA to participate.
- Categories: DATABASE and GENERAL. Latest topics first, 20 per page; replies oldest first, 30 per page.
- Topic form: title and body, category. Reply form: body. Plain escaped text supports line breaks and SQL snippets without HTML execution.
- ADMIN can lock/unlock or hide/restore topics and hide/restore replies. Hidden content is excluded from normal account/guest reads.
- Active final assessments pause forum reading and posting, matching the no-helper rule. Forum never changes scores or learning progress.

## Persistence and security

Supabase forum_topics and forum_replies store author UUID, bounded text, timestamps and moderation flags. Authenticated read policies restrict visibility and deny reads during active assessments; no anonymous access and no browser writes. Server queries project public author display names only, not email, auth records or roles.

Mutations use service-role-only RPCs. The API derives the user from authenticated claims; user IDs, moderation roles and timestamps are not accepted from the client. RPCs verify the service role and existing profile, serialize with the assessment-start advisory lock, reject active assessments, and enforce database quotas (5 topics/hour, 30 replies/hour per account). Replies additionally lock the topic row and reject locked/hidden topics. Moderation independently verifies ADMIN in the database. RLS remains enabled; no destructive delete UI.

## Verification

Test unsigned/guest writes, invalid input, foreign author spoofing, quota limits, locked/hidden topic reply denial, non-admin moderation, active-assessment blocking, author projection, ownership, mobile/desktop overflow, topic/reply persistence and SQL/HTML literal display. Synthetic QA data is cleaned separately from real user discussions.
